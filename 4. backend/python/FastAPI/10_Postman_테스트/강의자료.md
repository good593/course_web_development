# 10교시 — Postman 테스트

## 학습 목표

- Postman으로 API 요청을 보내고 응답을 검증할 수 있다
- FastAPI의 openapi.json을 Postman에 가져와 Collection을 자동 생성할 수 있다
- Environment 변수로 개발/운영 환경을 분리할 수 있다
- Tests 스크립트로 자동화된 API 테스트를 작성할 수 있다

## 9~11교시 역할 구분

10교시는 **이미 만들어진 API 문서를 Postman으로 가져와 테스트하는 방법**에 집중합니다.

| 교시 | 핵심 역할 | 주요 도구 |
|------|-----------|-----------|
| 9교시 | API 코드에 문서 메타데이터를 작성하고 Swagger UI 품질 높이기 | FastAPI, OpenAPI, Swagger UI |
| 10교시 | 만들어진 OpenAPI 스펙을 Postman으로 가져와 수동/반자동 테스트하기 | Postman, Environment, Tests |
| 11교시 | OpenAPI 스펙을 AI에 전달해 문서와 Collection을 자동 생성하기 | Claude, openapi.json, 자동화 파이프라인 |

## 1. Postman 설치

[https://www.postman.com/downloads](https://www.postman.com/downloads) 에서 다운로드합니다.

또는 CLI 버전인 **Newman**으로 CI/CD에서 실행할 수 있습니다.

```bash
npm install -g newman
```

---

## 2. FastAPI → Postman 자동 가져오기

FastAPI 서버를 실행하면 `/openapi.json`에서 전체 API 스펙을 제공합니다.  
이를 Postman에 가져오면 모든 엔드포인트가 Collection으로 자동 생성됩니다.

### 방법

1. FastAPI 서버 실행: `uvicorn main:app --reload`
2. 브라우저에서 `http://localhost:8000/openapi.json` 접속 → JSON 전체 복사 또는 파일 저장
3. Postman 열기 → **Import** 버튼 클릭
4. **Raw text** 탭에 JSON 붙여넣기 (또는 파일 선택) → **Continue** → **Import**

모든 엔드포인트가 자동으로 생성됩니다.

---

## 3. Environment 변수 설정

개발/운영 서버 URL을 변수로 관리해 환경 전환을 쉽게 합니다.

### Environment 생성

1. 우측 상단 **Environments** 패널 → **+** 클릭
2. 이름: `Local Development`
3. 변수 추가:

| Variable | Initial Value | Current Value |
|----------|--------------|---------------|
| `base_url` | `http://localhost:8000` | `http://localhost:8000` |
| `token` | `demo-admin-token` | `demo-admin-token` |

### 요청에서 변수 사용

```
GET {{base_url}}/products/1
Authorization: Bearer {{token}}
```

## 4. 기본 요청 작성

### GET 요청

```
Method : GET
URL    : {{base_url}}/products
Params : page=1, size=10
```

**Params 탭**에서 키-값으로 추가하면 URL에 자동으로 `?page=1&size=10`이 붙습니다.

### POST 요청

```
Method  : POST
URL     : {{base_url}}/products
Headers : Content-Type: application/json
Body    : raw / JSON
```

```json
{
    "name": "무선 마우스",
    "price": 35000,
    "stock": 100,
    "category": "전자제품"
}
```

### PATCH 요청

```
Method : PATCH
URL    : {{base_url}}/products/1
Body   : raw / JSON
```

```json
{
    "price": 29000,
    "stock": 80
}
```

## 5. Tests 스크립트 — 자동 검증

각 요청의 **Tests** 탭에 JavaScript 코드를 작성해 응답을 자동 검증합니다.

### 기본 패턴

```javascript
// 상태 코드 검증
pm.test("상태 코드는 200이어야 한다", () => {
    pm.response.to.have.status(200);
});

// 응답 시간 검증
pm.test("응답 시간은 500ms 미만이어야 한다", () => {
    pm.expect(pm.response.responseTime).to.be.below(500);
});

// JSON 파싱
const body = pm.response.json();

// 필드 존재 여부
pm.test("id 필드가 있어야 한다", () => {
    pm.expect(body).to.have.property("id");
});

// 필드 타입 검증
pm.test("price는 숫자여야 한다", () => {
    pm.expect(body.price).to.be.a("number");
});

// 필드 값 범위
pm.test("price는 0보다 커야 한다", () => {
    pm.expect(body.price).to.be.above(0);
});
```

### 인증 토큰 변수 사용

9교시 예제 서버는 실습용 관리자 토큰 `demo-admin-token`을 사용합니다.  
보호된 요청에는 Headers 탭에 다음 값을 추가합니다.

```http
Authorization: Bearer {{token}}
```

실무에서는 로그인 API 응답의 `access_token`을 `pm.environment.set("token", body.access_token)`으로 저장해 이어지는 요청에서 사용합니다.

## 6. Pre-request Script — 요청 전 처리

요청을 보내기 전에 실행되는 스크립트입니다.

```javascript
// 타임스탬프 생성
pm.environment.set("timestamp", new Date().toISOString());

// 동적 데이터 생성
const randomSuffix = Math.floor(Math.random() * 10000);
pm.environment.set("test_email", `test_${randomSuffix}@example.com`);
```

요청 Body에서 이 변수를 사용합니다.

```json
{
    "username": "testuser_{{$randomInt}}",
    "email": "{{test_email}}",
    "created_at": "{{timestamp}}"
}
```

## 7. Collection 구성 — 폴더로 시나리오 정리

```
📁 쇼핑몰 API
├── 📁 상품 관리
│   ├── 상품 목록 조회         GET  /products
│   ├── 상품 생성              POST /products
│   ├── 상품 단건 조회         GET  /products/{{product_id}}
│   ├── 상품 수정              PATCH /products/{{product_id}}
│   └── 상품 삭제              DELETE /products/{{product_id}}
│
├── 📁 주문 시나리오
│   ├── 1. 상품 목록 확인      GET  /products
│   ├── 2. 주문 생성           POST /orders
│   ├── 3. 주문 조회           GET  /orders/{{order_id}}
│   └── 4. 주문 취소           PATCH /orders/{{order_id}}/cancel
│
└── 📁 에러 케이스
    ├── 존재하지 않는 상품      GET  /products/99999
    ├── 재고 초과 주문          POST /orders
    └── 필수 필드 누락          POST /products
```

### Collection Runner로 전체 실행

1. Collection 우클릭 → **Run collection** 클릭
2. 실행 순서 확인 후 **Run** 클릭
3. 전체 테스트 결과 한눈에 확인

## 8. Collection 내보내기 / 팀 공유

### 내보내기

Collection 우클릭 → **Export** → **Collection v2.1** → JSON 파일 저장

팀원은 이 파일을 **Import**해서 바로 사용합니다.

### collection.json 예시 구조

`collection.json` 파일을 참고하세요. Postman에서 바로 가져올 수 있습니다.

```bash
# Import 후 사용법
# 1. Postman → Import → collection.json 선택
# 2. Environment → Local Development 선택
# 3. 서버 실행 후 요청 전송
```

## 9. Newman — CLI 테스트 자동화

Postman Collection을 CI/CD 파이프라인에서 실행합니다.

```bash
# 설치
npm install -g newman newman-reporter-htmlextra

# 실행
newman run collection.json \
  --environment environment.json \
  --reporters cli,htmlextra \
  --reporter-htmlextra-export report.html

# GitHub Actions 등에서 활용
```

## 10. 실습 순서

1. `09_Swagger_API문서화` 폴더의 서버 실행
2. `http://localhost:8000/openapi.json` → Postman Import

4. 상품 생성 → 조회 → 수정 → 삭제 순서로 요청 실행
5. 각 요청에 Tests 스크립트 추가
6. Collection Runner로 전체 시나리오 실행
7. `collection.json` 파일로 내보내기
