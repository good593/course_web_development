# 12교시: CRUD 기반 백엔드 서비스 설계

## 학습 목표

- 3계층 아키텍처(Router → Service → Repository)를 이해하고 구조화
- SQLAlchemy ORM으로 관계형 데이터 모델 설계
- Create / Update / Response 스키마 분리 원칙 적용
- 의존성 주입(Depends)으로 테스트 가능한 코드 구조 설계

---

## 1. 백엔드 서비스 계층 구조

### 왜 계층을 나누는가?

| 문제 | 해결 |
|------|------|
| 라우터에 SQL이 섞여 유지보수 어려움 | Repository 계층으로 DB 접근 격리 |
| 비즈니스 로직이 흩어짐 | Service 계층으로 로직 집중 |
| 단위 테스트가 불가능 | 계층별 독립 테스트 가능 |
| DB 교체 시 전면 수정 | Repository만 교체 |

### 3계층 구조

```
[클라이언트]
     ↓ HTTP 요청/응답
┌─────────────────────────────┐
│  Router (Presentation)      │  Pydantic 검증, 상태코드, 직렬화
└────────────┬────────────────┘
             ↓
┌─────────────────────────────┐
│  Service (Business Logic)   │  유효성 검사, 트랜잭션, 규칙 처리
└────────────┬────────────────┘
             ↓
┌─────────────────────────────┐
│  Repository (Data Access)   │  SQL 쿼리, DB CRUD
└────────────┬────────────────┘
             ↓
         [Database]
```

### 각 계층의 책임

```python
# Router — HTTP와 비즈니스 로직을 분리
@app.get("/posts/{post_id}", response_model=PostResponse)
def get_post(post_id: int, service: PostService = Depends(get_service)):
    return service.get_post(post_id)  # 비즈니스 로직은 Service에 위임

# Service — 비즈니스 규칙 처리
class PostService:
    def get_post(self, post_id: int) -> Post:
        post = self.repo.get_by_id(post_id)
        if not post:
            raise HTTPException(404, "게시글을 찾을 수 없습니다")
        return post

# Repository — DB 접근만 담당
class PostRepository:
    def get_by_id(self, post_id: int) -> Post | None:
        return self.db.get(post_id)  # SQL 또는 ORM 쿼리
```

## 2. 도메인 모델 설계

### 예제: 블로그 API

```
Category (카테고리)
  └── id, name, description

Post (게시글)
  └── id, title, content, summary, published
  └── category_id → Category  (N:1)
  └── created_at, updated_at

Comment (댓글)
  └── id, content, author
  └── post_id → Post  (N:1)
  └── created_at
```

### 관계 다이어그램

```
Category (1) ────< Post (1) ────< Comment
```

### 관계 설계 결정 사항

| 관계 | 카디널리티 | 설계 선택 |
|------|-----------|----------|
| Category → Post | 1:N | FK(category_id) in Post |
| Post → Comment | 1:N | FK(post_id) in Comment, cascade delete |
| Post 삭제 시 | — | Comment도 함께 삭제 (orphan 제거) |

## 3. SQLAlchemy 모델 설계

> **참고**: 이 섹션은 13교시에서 실제로 구현할 SQLAlchemy 코드를 **미리 설계 형태로** 보여줍니다.  
> 이번 교시의 `main.py`는 DB 설치 없이 바로 실행할 수 있도록 **인메모리 저장소**로 동일한 패턴을 구현합니다.  
> SQLAlchemy 실제 동작은 13교시에서 확인합니다.

### DB 연결 설정

```python
# database.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, declarative_base

DATABASE_URL = "sqlite:///./blog.db"

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()

def get_db():
    db = SessionLocal()
    try:
        yield db      # 요청 처리 동안 세션 유지
    finally:
        db.close()    # 요청 완료 후 반드시 닫기
```

### 모델 정의

```python
# models.py
from sqlalchemy import Column, Integer, String, Boolean, Text, ForeignKey, DateTime
from sqlalchemy.orm import relationship
from datetime import datetime

class Category(Base):
    __tablename__ = "categories"

    id          = Column(Integer, primary_key=True, index=True)
    name        = Column(String(100), unique=True, nullable=False)
    description = Column(String(500))

    posts = relationship("Post", back_populates="category")


class Post(Base):
    __tablename__ = "posts"

    id          = Column(Integer, primary_key=True, index=True)
    title       = Column(String(200), nullable=False, index=True)
    content     = Column(Text, nullable=False)
    summary     = Column(String(500))
    published   = Column(Boolean, default=False)
    category_id = Column(Integer, ForeignKey("categories.id"), nullable=True)
    created_at  = Column(DateTime, default=datetime.utcnow)
    updated_at  = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)

    category = relationship("Category", back_populates="posts")
    comments = relationship("Comment", back_populates="post", cascade="all, delete-orphan")


class Comment(Base):
    __tablename__ = "comments"

    id         = Column(Integer, primary_key=True, index=True)
    content    = Column(Text, nullable=False)
    author     = Column(String(100), nullable=False)
    post_id    = Column(Integer, ForeignKey("posts.id"), nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)

    post = relationship("Post", back_populates="comments")
```

### 관계 옵션 정리

| 옵션 | 설명 |
|------|------|
| `back_populates` | 양방향 참조 — `post.category`, `category.posts` 모두 사용 가능 |
| `cascade="all, delete-orphan"` | Post 삭제 시 Comment 자동 삭제 |
| `index=True` | WHERE/ORDER BY에 자주 쓰이는 컬럼에 인덱스 추가 |
| `nullable=False` | DB 수준에서 NOT NULL 강제 |
| `onupdate=datetime.utcnow` | UPDATE 시 자동으로 현재 시각 갱신 |

## 4. Pydantic 스키마 설계

### Create / Update / Response 분리

```python
# schemas.py

# ── Category ─────────────────────────────────────────────
class CategoryCreate(BaseModel):
    name: str = Field(..., max_length=100)
    description: str | None = None

class CategoryResponse(BaseModel):
    id: int
    name: str
    description: str | None = None
    model_config = ConfigDict(from_attributes=True)

# ── Post ─────────────────────────────────────────────────
class PostCreate(BaseModel):
    title: str = Field(..., max_length=200)
    content: str
    category_id: int | None = None

class PostUpdate(BaseModel):                    # 모든 필드 Optional
    title: str | None = Field(None, max_length=200)
    content: str | None = None
    summary: str | None = None
    published: bool | None = None
    category_id: int | None = None

class PostResponse(BaseModel):                  # DB 필드 포함
    id: int
    title: str
    content: str
    summary: str | None
    published: bool
    created_at: datetime
    category: CategoryResponse | None = None
    model_config = ConfigDict(from_attributes=True)

# ── Comment ───────────────────────────────────────────────
class CommentCreate(BaseModel):
    content: str
    author: str = Field(..., max_length=100)

class CommentResponse(BaseModel):
    id: int
    content: str
    author: str
    created_at: datetime
    model_config = ConfigDict(from_attributes=True)
```

### 스키마 목적별 규칙

| 스키마 | 특징 |
|--------|------|
| `XxxCreate` | 필수 필드는 `...`, 클라이언트가 제공하는 값만 |
| `XxxUpdate` | 모든 필드 `None` 가능, `exclude_unset=True` 사용 |
| `XxxResponse` | `id`, 타임스탬프 포함, `from_attributes=True` |

## 5. Repository 패턴

```python
class PostRepository:
    def __init__(self, db: Session):
        self.db = db

    def get_by_id(self, post_id: int) -> Post | None:
        return self.db.query(Post).filter(Post.id == post_id).first()

    def get_list(
        self,
        skip: int = 0,
        limit: int = 20,
        category_id: int | None = None,
        published_only: bool = False,
    ) -> list[Post]:
        q = self.db.query(Post)
        if category_id:
            q = q.filter(Post.category_id == category_id)
        if published_only:
            q = q.filter(Post.published == True)
        return q.order_by(Post.created_at.desc()).offset(skip).limit(limit).all()

    def create(self, data: PostCreate) -> Post:
        post = Post(**data.model_dump())
        self.db.add(post)
        self.db.commit()
        self.db.refresh(post)    # DB 기본값(id, created_at) 반영
        return post

    def update(self, post: Post, data: PostUpdate) -> Post:
        for field, value in data.model_dump(exclude_unset=True).items():
            setattr(post, field, value)
        self.db.commit()
        self.db.refresh(post)
        return post

    def delete(self, post: Post) -> None:
        self.db.delete(post)
        self.db.commit()
```

### `exclude_unset=True` 의 중요성

```python
data = PostUpdate(title="새 제목")  # content는 전달하지 않음

data.model_dump()                   # {"title": "새 제목", "content": None}
data.model_dump(exclude_unset=True) # {"title": "새 제목"}  ← content 덮어쓰지 않음
```

## 6. Service 패턴

```python
class PostService:
    def __init__(self, db: Session):
        self.repo = PostRepository(db)
        self.category_repo = CategoryRepository(db)

    def get_post(self, post_id: int) -> Post:
        post = self.repo.get_by_id(post_id)
        if not post:
            raise HTTPException(404, detail="게시글을 찾을 수 없습니다")
        return post

    def create_post(self, data: PostCreate) -> Post:
        if data.category_id:
            if not self.category_repo.get_by_id(data.category_id):
                raise HTTPException(400, detail="존재하지 않는 카테고리입니다")
        return self.repo.create(data)

    def update_post(self, post_id: int, data: PostUpdate) -> Post:
        post = self.get_post(post_id)
        return self.repo.update(post, data)

    def publish_post(self, post_id: int) -> Post:
        post = self.get_post(post_id)
        if post.published:
            raise HTTPException(400, detail="이미 공개된 게시글입니다")
        return self.repo.update(post, PostUpdate(published=True))

    def delete_post(self, post_id: int) -> None:
        post = self.get_post(post_id)
        self.repo.delete(post)
```

## 7. 의존성 주입

```python
# Service를 Depends로 주입
def get_post_service(db: Session = Depends(get_db)) -> PostService:
    return PostService(db)

@app.get("/posts/{post_id}", response_model=PostResponse)
def read_post(
    post_id: int,
    service: PostService = Depends(get_post_service),
):
    return service.get_post(post_id)

@app.post("/posts", response_model=PostResponse, status_code=201)
def create_post(
    data: PostCreate,
    service: PostService = Depends(get_post_service),
):
    return service.create_post(data)
```

## 핵심 설계 원칙 정리

| 원칙 | 적용 방식 |
|------|----------|
| 단일 책임 (SRP) | Router = HTTP, Service = 로직, Repository = DB |
| 의존성 역전 (DIP) | Service는 Repository 인터페이스에만 의존 |
| 스키마 목적 분리 | Create / Update / Response 분리 |
| Cascade 전략 명시 | `delete-orphan`으로 고아 레코드 방지 |
| 인덱스 설계 | 검색 기준 컬럼(title, category_id)에 `index=True` |
