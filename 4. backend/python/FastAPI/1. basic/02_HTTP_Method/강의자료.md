# 2교시 — HTTP Method 이해

**소요시간:** 90분 (이론 45분 + 실습 45분)

---

## 1. HTTP 메서드 전체 개요

HTTP 메서드는 서버에게 **"무엇을 하고 싶은지"** 전달하는 동사다.

| 메서드 | 역할 | 멱등성 | Body |
|--------|------|--------|------|
| **GET** | 조회 | ✅ | ❌ |
| **POST** | 생성 | ❌ | ✅ |
| **PUT** | 전체 수정 | ✅ | ✅ |
| **PATCH** | 부분 수정 | ❌ | ✅ |
| **DELETE** | 삭제 | ✅ | ❌ |

> **멱등성(Idempotent)** : 같은 요청을 여러 번 보내도 결과가 동일한 성질
> - `GET /users/1` → 몇 번 호출해도 같은 유저 반환 ✅
> - `POST /users` → 호출할 때마다 새 유저 생성 ❌

---

## 2. GET vs POST 핵심 차이

### GET

```
GET /search?keyword=fastapi&page=1 HTTP/1.1
Host: api.example.com
```

- 데이터를 **URL에 포함** (Query String)
- **조회 전용** — 서버 상태를 바꾸지 않는다
- 브라우저 히스토리/북마크 가능
- URL 길이 제한 있음 (~2000자)
- **민감한 정보 전송 금지** (URL이 로그에 남음)

### POST

```
POST /users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
    "name": "홍길동",
    "email": "hong@example.com",
    "password": "secret123"
}
```

- 데이터를 **Request Body에 포함**
- **생성 / 처리** 목적
- URL에 데이터가 노출되지 않음
- 데이터 크기 제한 없음
- 민감한 정보 전송 가능

### 비교 요약

| 항목 | GET | POST |
|------|-----|------|
| 데이터 위치 | URL Query String | Request Body |
| 데이터 크기 | 제한 있음 | 제한 없음 |
| 보안 | URL에 노출 | Body에 숨김 |
| 캐싱 | 가능 | 불가 |
| 목적 | 조회 | 생성/처리 |
| 멱등성 | ✅ | ❌ |

## 3. HTTP 상태 코드

서버가 클라이언트에게 **"결과가 어떻게 됐는지"** 알려주는 숫자 코드

### 2xx — 성공

| 코드 | 이름 | 언제 사용 |
|------|------|----------|
| **200** | OK | 일반적인 성공 (GET, PUT, PATCH) |
| **201** | Created | 리소스 생성 성공 (POST) |
| **204** | No Content | 성공했지만 응답 본문 없음 (DELETE) |

### 4xx — 클라이언트 오류

| 코드 | 이름 | 언제 사용 |
|------|------|----------|
| **400** | Bad Request | 잘못된 요청 (형식 오류, 비즈니스 로직 위반) |
| **401** | Unauthorized | 인증 필요 |
| **403** | Forbidden | 권한 없음 |
| **404** | Not Found | 리소스 없음 |
| **422** | Unprocessable Entity | 데이터 검증 실패 (FastAPI 기본) |

### 5xx — 서버 오류

| 코드 | 이름 | 언제 사용 |
|------|------|----------|
| **500** | Internal Server Error | 서버 내부 오류 |
| **503** | Service Unavailable | 서버 일시 중단 |

## 4. HTTP Request 구성 요소

```
POST /users/42/orders?notify=true HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGc...
Content-Type: application/json

{
    "product_id": 10,
    "quantity": 3
}
```

| 구성 요소 | 예시 | 설명 |
|-----------|------|------|
| **Method** | `POST` | 행위 |
| **Path** | `/users/42/orders` | 리소스 경로 |
| **Path Parameter** | `42` | URI 내 변수 |
| **Query Parameter** | `notify=true` | URL `?` 뒤 키=값 |
| **Header** | `Authorization: Bearer ...` | 메타데이터 (인증, 타입 등) |
| **Body** | `{"product_id": 10, ...}` | 전송 데이터 |

## 5. 실습 — curl / HTTPie로 직접 요청하기

### 실습 서버 실행

```bash
uvicorn main:app --reload
```

### curl 사용법

```bash
# GET 요청
curl http://127.0.0.1:8000/

# GET + Query Parameter
curl "http://127.0.0.1:8000/search?keyword=fastapi"

# POST 요청 (JSON Body)
curl -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "노트북", "price": 1500000}'

# 응답 상태 코드 확인
curl -I http://127.0.0.1:8000/
```

### HTTPie 사용법 (더 직관적)

```bash
pip install httpie

# GET
http GET http://127.0.0.1:8000/

# GET + Query Parameter
http GET http://127.0.0.1:8000/search keyword==fastapi

# POST (자동으로 Content-Type: application/json 설정)
http POST http://127.0.0.1:8000/items name="노트북" price:=1500000
```

### Swagger UI에서 요청 분석

1. `http://127.0.0.1:8000/docs` 접속
2. 엔드포인트 클릭 → **Parameters** 확인 (Path / Query 구분)
3. **Request body** 섹션 확인
4. "Try it out" → "Execute" → **Response** 분석
   - Response Code
   - Response Headers
   - Response Body

## 6. REST URI 설계 규칙

### 좋은 URI vs 나쁜 URI

```
# 리소스는 명사, 복수형 사용
✅ GET  /articles
✅ GET  /articles/1
✅ POST /articles

❌ GET  /getArticles
❌ GET  /article/1       (단수)
❌ POST /createArticle

# 계층 구조 표현
✅ GET /users/42/orders        (42번 유저의 주문 목록)
✅ GET /users/42/orders/7      (42번 유저의 7번 주문)

# 필터/정렬/페이지는 Query Parameter
✅ GET /articles?category=tech&sort=latest&page=2
❌ GET /articles/tech/latest/page/2
```

### 상태 코드와 메서드 조합

```
POST   /users          → 201 Created
GET    /users          → 200 OK
GET    /users/99       → 200 OK (있을 때), 404 Not Found (없을 때)
PUT    /users/99       → 200 OK
DELETE /users/99       → 204 No Content
POST   /users (중복)   → 400 Bad Request 또는 409 Conflict
```

## 7. 핵심 요약

| 개념 | 핵심 포인트 |
|------|------------|
| GET | 조회, URL에 데이터, 멱등성 있음 |
| POST | 생성, Body에 데이터, 멱등성 없음 |
| 상태 코드 | 200(성공), 201(생성), 400(클라이언트오류), 404(없음), 422(검증실패) |
| URI 설계 | 명사+복수형, 계층 구조, 필터는 Query Parameter |
