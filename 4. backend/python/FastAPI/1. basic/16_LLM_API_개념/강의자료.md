## 1. LLM이란?

### 언어 모델의 작동 방식

LLM(Large Language Model)은 **다음 토큰을 예측하는 확률 모델**입니다.

```
입력: "오늘 날씨가"
↓
모델 내부: [오늘:0.3%][날씨:0.5%][가:0.8%]...[맑다:12.3%][흐리다:9.1%]...
↓
출력: "맑다"  (가장 높은 확률의 토큰 선택)
```

학습 과정:
1. 수천억 개의 텍스트에서 패턴 학습
2. Transformer 아키텍처로 문맥(context) 이해
3. RLHF(인간 피드백 강화학습)로 응답 품질 개선

### Transformer의 핵심 — Attention

```
"나는 은행에 갔다" → 여기서 '은행'은 금융 기관?  나무?

Attention 메커니즘이 문맥을 보고 의미를 결정:
'나는' + '갔다' + 전체 문장 → '은행' = 금융 기관
```

## 2. 토큰(Token) 이해

### 토큰이란?

텍스트를 LLM이 처리하는 최소 단위입니다. 단어와 다릅니다.

```
"Hello, world!"  →  ["Hello", ",", " world", "!"]  (4 tokens)
"안녕하세요"     →  ["안녕", "하세", "요"]          (3 tokens, 한국어는 더 많음)
```

**왜 중요한가?**
- API 비용은 **입력 토큰 + 출력 토큰** 합산으로 계산
- 모델마다 처리 가능한 최대 토큰(컨텍스트 윈도우)이 정해져 있음

### 토큰 수 감각 잡기

| 텍스트 | 대략적인 토큰 수 |
|--------|----------------|
| 영어 1,000 단어 | ~750 토큰 |
| 한국어 1,000 글자 | ~500~900 토큰 |
| 평균 API 요청 | 100~500 토큰 |
| 긴 문서 요약 요청 | 1,000~5,000 토큰 |

### 토큰 확인 도구

- OpenAI Tokenizer: platform.openai.com/tokenizer
- Google의 `count_tokens` API (실습에서 직접 확인)

## 3. 컨텍스트 윈도우(Context Window)

모델이 한 번에 볼 수 있는 최대 토큰 수입니다.

```
┌──────────────────────────────────────────┐
│           컨텍스트 윈도우 (예: 128K)       │
│                                          │
│  [시스템 지시문] + [대화 기록] + [현재 질문] │
│                                          │
│  ← 이 합계가 128,000 토큰을 넘으면 안 됨  │
└──────────────────────────────────────────┘
```

| 모델 | 컨텍스트 윈도우 |
|------|----------------|
| Gemini 3.5 Flash | 1,000,000 토큰 수준 |
| Claude Opus 4.8 | 1,048,576 토큰 |
| GPT-4o | 128,000 토큰 |

## 4. LLM API 호출 흐름

```
[내 코드]                [LLM API 서버]
    │                          │
    │──── POST /generate ─────>│
    │  {                       │
│    model: "gemini-3.5-flash",   │
    │    contents: "질문",     │
    │    temperature: 0.7      │
    │  }                       │
    │                          │
    │<──── JSON 응답 ──────────│
    │  {                       │
    │    text: "답변",         │
    │    usage: {              │
    │      input_tokens: 15,   │
    │      output_tokens: 42   │
    │    }                     │
    │  }                       │
```

### API 키 인증

모든 LLM API는 **API 키**로 요청자를 식별합니다.

```
Authorization: Bearer sk-ant-...   ← Claude
X-goog-api-key: AIza...            ← Gemini (헤더)
Authorization: Bearer sk-proj-...  ← OpenAI
```

> 절대 코드에 직접 넣지 마세요 — 환경 변수(.env) 사용

## 5. 과금 구조 이해

### 토큰 기반 과금

```
비용 = (입력 토큰 × 입력 단가) + (출력 토큰 × 출력 단가)
```

**예시 계산** (Gemini 3.5 Flash 표준 유료 단가 기준):

| 항목 | 값 |
|------|-----|
| 입력 토큰 | 1,000 |
| 출력 토큰 | 500 |
| 입력 단가 | $1.50 / 1M 토큰 |
| 출력 단가 | $9.00 / 1M 토큰 |
| 총 비용 | $0.0015 + $0.0045 = **약 $0.0060** |

### 무료 티어 (Gemini Flash)

Gemini API는 학습·소규모 실습을 위한 **무료 티어**를 제공합니다.  
다만 무료 한도와 지원 모델은 수시로 바뀔 수 있으므로, 수업 직전 Google AI Studio의 Rate limits/가격 페이지에서 확인합니다.

> 강의 실습 비용을 설명할 때는 무료 한도를 제외한 표준 유료 단가로 계산하면 안전합니다.

## 7. API vs 직접 구축 비교

```
┌─────────────────────────────┐   ┌─────────────────────────────┐
│         API 사용             │   │       직접 구축               │
│  장점                        │   │  장점                         │
│  · 즉시 사용 가능             │   │  · 데이터 프라이버시           │
│  · 최신 모델 자동 반영        │   │  · 반복 비용 없음              │
│  · 인프라 관리 불필요         │   │  · 모델 커스텀 가능            │
│                              │   │                              │
│  단점                        │   │  단점                         │
│  · 토큰당 비용                │   │  · GPU 인프라 필요             │
│  · 데이터 외부 전송           │   │  · 전문 ML 엔지니어 필요       │
│  · 네트워크 레이턴시          │   │  · 수개월의 구축 기간          │
└─────────────────────────────┘   └─────────────────────────────┘
```

**현실적인 선택**: 스타트업/서비스 개발에서는 API 사용이 압도적으로 유리합니다.

## 8. 생성형 AI API 활용 패턴

### 단일 호출 (Single Turn)

```
질문 ─────────────────────────────────────────> [LLM]
                                                   │
답변 <─────────────────────────────────────────── │
```
용도: 번역, 분류, 요약, 코드 생성

### 멀티턴 대화 (Multi-Turn)

```
[사용자] 안녕하세요  ──> [LLM] 안녕하세요!
[사용자] 파이썬이란? ──> [LLM] 파이썬은 ... (앞 대화 기억)
[사용자] 더 쉽게     ──> [LLM] 더 쉽게 말하면 ... (여전히 파이썬 문맥)
```
용도: 챗봇, 대화형 어시스턴트

### RAG (검색 증강 생성)

```
질문 → [검색 DB] → 관련 문서 → [LLM에 함께 전달] → 답변
```
용도: 사내 문서 기반 Q&A, 최신 정보 기반 응답
