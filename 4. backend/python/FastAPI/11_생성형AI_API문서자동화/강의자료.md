# 11교시 — 생성형 AI를 활용한 API 문서 자동화

## 학습 목표

- FastAPI의 openapi.json을 Groq API에 전달해 마크다운 문서를 자동 생성할 수 있다
- Groq로 Postman Collection JSON을 자동 생성할 수 있다
- API 코드를 분석해 README와 사용 가이드를 자동화할 수 있다
- 문서 자동화 워크플로우를 실무 프로젝트에 적용할 수 있다

## 9~11교시 역할 구분

11교시는 **OpenAPI 스펙을 입력으로 받아 문서와 Postman Collection을 자동 생성하는 방법**에 집중합니다.

| 교시 | 핵심 역할 | 주요 도구 |
|------|-----------|-----------|
| 9교시 | API 코드에 문서 메타데이터를 작성하고 Swagger UI 품질 높이기 | FastAPI, OpenAPI, Swagger UI |
| 10교시 | 만들어진 OpenAPI 스펙을 Postman으로 가져와 수동/반자동 테스트하기 | Postman, Environment, Tests |
| 11교시 | OpenAPI 스펙을 AI에 전달해 문서와 Collection을 자동 생성하기 | Groq, openapi.json, 자동화 파이프라인 |

---

## 1. API 문서 자동화가 필요한 이유

| 문제 | 설명 |
|------|------|
| 문서 누락 | 개발 속도에 문서화가 따라가지 못함 |
| 문서 불일치 | 코드는 바뀌었는데 문서는 구버전 그대로 |
| 작성 부담 | 엔드포인트 20개 → 예시·설명 수동 작성 시간 과다 |
| 팀 규칙 불일치 | 작성자마다 문서 스타일이 다름 |

생성형 AI를 활용하면 **코드 → 문서**를 자동화해 항상 최신 상태를 유지할 수 있습니다.

## 2. 자동화 흐름

```
FastAPI 서버
     │
     ▼ GET /openapi.json

     │
     ▼
Groq API
     │
     ├──► 마크다운 API 문서
     ├──► Postman Collection JSON
     └──► README.md
```

## 3. openapi.json 읽기

FastAPI 서버가 실행 중일 때 스펙을 가져오는 두 가지 방법입니다.

### 방법 1 — HTTP 요청으로 가져오기 (서버 실행 중)

```python
import httpx

response = httpx.get("http://localhost:8000/openapi.json")
openapi_spec = response.json()
```

### 방법 2 — FastAPI 앱 객체에서 직접 추출 (서버 없이)

```python
import json
from main import app  # FastAPI 앱 임포트

openapi_spec = app.openapi()
spec_text = json.dumps(openapi_spec, ensure_ascii=False, indent=2)
```

## 4. 마크다운 API 문서 자동 생성

```python
import json

import httpx
from dotenv import load_dotenv
from groq import Groq

load_dotenv()  # .env 파일에서 GROQ_API_KEY 로드
client = Groq()

MODEL = "openai/gpt-oss-120b"

def build_openapi_url(base_or_spec_url: str) -> str:
    url = base_or_spec_url.rstrip("/")
    if url.endswith("/openapi.json"):
        return url
    return f"{url}/openapi.json"


def fetch_openapi_spec(url: str = "http://localhost:8000") -> dict:
    spec_url = build_openapi_url(url)
    response = httpx.get(spec_url, timeout=5)
    response.raise_for_status()
    return response.json()


def stream_groq(prompt: str, max_tokens: int = 8192, reasoning_effort: str = "medium") -> str:
    stream = client.chat.completions.create(
        model=MODEL,
        messages=[{"role": "user", "content": prompt}],
        max_completion_tokens=max_tokens,
        reasoning_effort=reasoning_effort,
        reasoning_format="hidden",
        temperature=0.2,
        stream=True,
    )

    result = []
    for chunk in stream:
        if not chunk.choices:
            continue

        text = chunk.choices[0].delta.content or ""
        print(text, end="", flush=True)
        result.append(text)

    return "".join(result)


def generate_api_docs(spec: dict) -> str:
    spec_text = json.dumps(spec, ensure_ascii=False, indent=2)

    prompt = f"""다음 OpenAPI 스펙을 분석해서 개발자용 API 문서를 마크다운으로 작성해줘.

[포함할 내용]
1. API 개요 (제목, 설명, 버전, 베이스 URL)
2. 인증 방법
3. 엔드포인트 목록 (표 형식)
4. 각 엔드포인트 상세:
   - 메서드 + 경로
   - 설명
   - 요청 파라미터 (path, query, body)
   - 요청 예시 (curl)
   - 응답 예시 (JSON)
   - 에러 코드 목록
5. 공통 에러 코드 표

[OpenAPI 스펙]
{spec_text}
"""
    return stream_groq(prompt, max_tokens=8192, reasoning_effort="medium")


def save_docs(content: str, filename: str = "API_DOCS.md"):
    with open(filename, "w", encoding="utf-8") as f:
        f.write(content)
    print(f"\n\n문서가 '{filename}'에 저장되었습니다.")
```

## 5. Postman Collection 자동 생성

````python
import json
import re

def generate_postman_collection(spec: dict) -> str:
    spec_text = json.dumps(spec, ensure_ascii=False, indent=2)

    prompt = f"""다음 OpenAPI 스펙을 Postman Collection v2.1 JSON 형식으로 변환해줘.

[요구사항]
1. collection.info.name은 API 제목 사용
2. 모든 엔드포인트 포함
3. 요청 URL에 {{{{base_url}}}} 변수 사용 (예: {{{{base_url}}}}/products)
4. Content-Type: application/json 헤더 추가
5. POST/PUT/PATCH는 예시 request body 포함 (스펙의 schema 기반)
6. 각 요청에 기본 Tests 스크립트 포함:
   - 상태 코드 검증 (200 또는 201)
   - 응답 시간 500ms 미만
   - 응답이 JSON인지 확인
7. 태그별로 폴더(item) 그룹화
8. 완성된 JSON만 출력 (설명 없이)

```json ... ``` 블록으로 감싸서 출력해줘.

[OpenAPI 스펙]
{spec_text}
"""

    print("Postman Collection 생성 중...\n")
    full_response = stream_groq(prompt, max_tokens=16000, reasoning_effort="low")

    # JSON 블록 추출
    pattern = r"```json\n(.*?)```"
    matches = re.findall(pattern, full_response, re.DOTALL)
    if matches:
        return matches[0]
    return full_response


def save_collection(collection_json: str, filename: str = "collection.json"):
    # JSON 유효성 검사 후 저장
    parsed = json.loads(collection_json)
    with open(filename, "w", encoding="utf-8") as f:
        json.dump(parsed, f, ensure_ascii=False, indent=2)
    print(f"\nCollection이 '{filename}'에 저장되었습니다.")
    print("Postman → Import → 파일 선택으로 가져올 수 있습니다.")
````

## 6. README 자동 생성

```python
def generate_readme(spec: dict, project_description: str = "") -> str:
    spec_text = json.dumps(spec, ensure_ascii=False, indent=2)

    prompt = f"""다음 OpenAPI 스펙을 기반으로 GitHub README.md를 작성해줘.

[포함할 섹션]
1. 프로젝트 제목 및 뱃지
2. 프로젝트 소개 (1~3문장)
3. 주요 기능 목록
4. 기술 스택
5. 빠른 시작 (설치 → 환경 설정 → 실행)
6. API 엔드포인트 요약 표
7. 환경 변수 목록

[추가 컨텍스트]
{project_description}

[OpenAPI 스펙]
{spec_text}
"""
    return stream_groq(prompt, max_tokens=4096, reasoning_effort="medium")
```

## 7. 증분 문서화 — 변경된 엔드포인트만 업데이트

코드가 바뀔 때마다 전체 문서를 재생성하면 비효율적입니다.  
이전 스펙과 비교해 **변경된 부분만** 업데이트하는 방식입니다.

```python
import json
from pathlib import Path

def get_changed_endpoints(old_spec: dict, new_spec: dict) -> list[dict]:
    """두 스펙을 비교해 변경된 엔드포인트 목록을 반환합니다."""
    changes = []
    old_paths = old_spec.get("paths", {})
    new_paths = new_spec.get("paths", {})

    for path, methods in new_paths.items():
        for method, details in methods.items():
            old_details = old_paths.get(path, {}).get(method)
            if old_details != details:
                changes.append({
                    "path": path,
                    "method": method.upper(),
                    "details": details,
                    "is_new": old_details is None,
                })

    return changes


def update_docs_for_changes(changes: list[dict]) -> str:
    if not changes:
        print("변경된 엔드포인트가 없습니다.")
        return ""

    changes_text = json.dumps(changes, ensure_ascii=False, indent=2)
    prompt = f"""다음 변경된 API 엔드포인트에 대한 문서를 마크다운으로 작성해줘.
각 엔드포인트의 설명, curl 예시, 응답 예시를 포함해줘.

[변경사항]
{changes_text}
"""
    return stream_groq(prompt, max_tokens=4096, reasoning_effort="medium")
```

## 8. 전체 자동화 파이프라인

```python
# main.py의 run_pipeline() 함수 참고

def run_pipeline(server_url: str = "http://localhost:8000"):
    print("=" * 60)
    print("API 문서 자동화 파이프라인 시작")
    print("=" * 60)

    # 1단계: 스펙 수집
    print("\n[1/4] OpenAPI 스펙 수집 중...")
    spec = fetch_openapi_spec(server_url)
    print(f"  엔드포인트 수: {sum(len(v) for v in spec.get('paths', {}).values())}")

    # 2단계: 마크다운 API 문서 생성
    print("\n[2/4] 마크다운 API 문서 생성 중...")
    docs = generate_api_docs(spec)
    save_docs(docs, "output/API_DOCS.md")

    # 3단계: Postman Collection 생성
    print("\n[3/4] Postman Collection 생성 중...")
    collection = generate_postman_collection(spec)
    save_collection(collection, "output/collection.json")

    # 4단계: README 생성
    print("\n[4/4] README 생성 중...")
    readme = generate_readme(spec)
    save_docs(readme, "output/README.md")

    print("\n" + "=" * 60)
    print("완료! output/ 폴더를 확인하세요.")
    print("=" * 60)
```

## 10. 모델과 토큰 사용량 확인

예제에서는 문서 생성에 `openai/gpt-oss-120b` 모델을 사용합니다. 긴 OpenAPI 스펙을 처리해야 하므로 응답 토큰 한도를 충분히 크게 잡고, 복잡한 문서 생성에는 `reasoning_effort="medium"`을 사용합니다.

스트리밍 응답에서 사용량까지 확인하려면 `stream_options={"include_usage": True}`를 추가합니다.

```python
stream = client.chat.completions.create(
    model="openai/gpt-oss-120b",
    messages=[{"role": "user", "content": "간단한 API 문서 템플릿을 만들어줘."}],
    max_completion_tokens=1024,
    reasoning_effort="medium",
    reasoning_format="hidden",
    stream=True,
    stream_options={"include_usage": True},
)

usage = None
for chunk in stream:
    if getattr(chunk, "usage", None) is not None:
        usage = chunk.usage

    if chunk.choices:
        print(chunk.choices[0].delta.content or "", end="")

if usage:
    print(f"\n총 토큰: {usage.total_tokens}")
```

## 핵심 정리

| 기능 | 방법 |
|------|------|
| 스펙 수집 | `GET /openapi.json` → JSON |
| Groq 클라이언트 | `client = Groq()` |
| 마크다운 문서 | OpenAPI JSON → Groq → .md 파일 |
| Postman Collection | OpenAPI JSON → Groq → collection.json |
| README 생성 | OpenAPI JSON → Groq → README.md |
| 스트리밍 | `stream=True`, `chunk.choices[0].delta.content` |
| 추론 강도 | `reasoning_effort` 값: `low`, `medium`, `high` |
| 증분 업데이트 | 이전 스펙과 diff → 변경분만 재생성 |
| 파이프라인 | 스펙 수집 → 문서 → Collection → README 순 실행 |
