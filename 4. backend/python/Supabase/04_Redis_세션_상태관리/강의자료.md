# 4교시: Redis 세션 관리와 사용자 상태 유지

**소요시간:** 90분 (이론 25분 + 실습 65분)  
**사전 지식:** 3교시(Supabase Auth), Docker 기본 사용법

---

## 학습 목표

- Redis의 인메모리 키-값 저장 구조를 이해한다
- String, Hash, List, Set, Sorted Set의 쓰임을 구분한다
- TTL로 자동 만료되는 세션을 구현한다
- FastAPI 요청에서 `X-Session-Id` 헤더로 사용자 상태를 유지한다
- Redis List로 짧은 대화 이력을 저장하고 최근 N개만 유지한다

## 1. Redis란 무엇인가

Redis는 **메모리에 데이터를 저장**하는 초고속 키-값 저장소입니다.

```
PostgreSQL (Supabase)         Redis
디스크 저장                   메모리 저장
복잡한 쿼리 (JOIN, 집계)      단순 키 기반 조회
영구 보관                     짧은 생명주기 (TTL)
수 ms ~ 수십 ms               수십 µs (마이크로초)
```

### 언제 Redis를 쓰는가

| 사용 사례 | Redis가 어울리는 이유 |
|-----------|----------------------|
| 로그인 세션 | TTL로 자동 만료 가능 |
| 사용자 현재 상태 | 빠르게 읽고 자주 바뀜 |
| 최근 대화 이력 | 최근 N개만 빠르게 유지 |
| DB 조회 결과 캐시 | 같은 쿼리를 반복 방지 |
| Rate Limit | 짧은 시간 동안 요청 횟수 집계 |

## 2. Redis 자료구조

Redis는 5가지 핵심 자료구조를 제공합니다. 이번 실습에서는 **Hash**와 **List**를 중심으로 사용합니다.

### String

가장 단순한 형태. 하나의 키에 하나의 값.

```bash
SET user:count 42        # 저장
GET user:count           # "42"
INCR user:count          # "43" (원자적 증가)
SET session:abc "user-1" # 세션 토큰
```

### Hash

하나의 키에 여러 필드(딕셔너리처럼).

```bash
HSET session:abc user_id "u1" display_name "김학생" status "online"
HGETALL session:abc
# 1) "user_id"
# 2) "u1"
# 3) "display_name"
# 4) "김학생"
# 5) "status"
# 6) "online"
HGET session:abc user_id  # "u1"
HSET session:abc status "away"  # 한 필드만 수정
```

### List

순서가 있는 값 목록. 대화 이력, 작업 큐에 사용.

```bash
RPUSH chat:abc '{"role":"user","content":"안녕"}'    # 오른쪽에 추가
RPUSH chat:abc '{"role":"assistant","content":"안녕하세요"}'
LRANGE chat:abc 0 -1   # 전체 조회
LTRIM  chat:abc -50 -1 # 최근 50개만 유지 (나머지 삭제)
LLEN   chat:abc        # 메시지 개수
```

### Set

중복 없는 집합.

```bash
SADD  online_users "user1"
SADD  online_users "user2"
SMEMBERS online_users  # {"user1", "user2"}
SISMEMBER online_users "user1"  # 1 (있음)
SREM  online_users "user1"
```

### Sorted Set

점수(score)를 기준으로 정렬되는 집합. 랭킹, 시간순 데이터에 사용.

```bash
ZADD  leaderboard 100 "user1"
ZADD  leaderboard 200 "user2"
ZADD  leaderboard 150 "user3"
ZRANGE leaderboard 0 -1 WITHSCORES  # 점수 오름차순
# user1 100 / user3 150 / user2 200
ZREVRANGE leaderboard 0 2  # 상위 3명 (점수 내림차순)
```

| 자료구조 | 주요 명령 | 이번 실습 |
|----------|-----------|-----------|
| String | `SET`, `GET`, `INCR` | - |
| Hash | `HSET`, `HGET`, `HGETALL` | 세션 저장 |
| List | `RPUSH`, `LRANGE`, `LTRIM` | 대화 이력 |
| Set | `SADD`, `SMEMBERS` | - |
| Sorted Set | `ZADD`, `ZRANGE` | - |

## 3. TTL(Time To Live)

TTL은 키가 **자동으로 사라지기까지 남은 시간(초)**입니다.

```bash
SET session:abc "user-1"
EXPIRE session:abc 1800   # 30분 후 자동 삭제
TTL session:abc           # 남은 초 확인 (예: 1795)
TTL session:abc           # 만료 후: -2 (없음)
PERSIST session:abc       # TTL 제거 (영구 보관으로 변경)
```

Python에서:

```python
r.hset("session:abc", mapping={"user_id": "u1"})
r.expire("session:abc", 1800)       # 30분
r.ttl("session:abc")                # 남은 초 반환
```

### TTL 갱신 패턴 (Sliding Expiry)

사용자가 활동할 때마다 TTL을 다시 설정합니다.

```python
def get_session(session_id: str) -> dict:
    data = r.hgetall(f"session:{session_id}")
    if not data:
        raise HTTPException(401, "세션이 없거나 만료되었습니다")
    
    # 활동할 때마다 TTL 갱신 (30분 연장)
    r.expire(f"session:{session_id}", SESSION_TTL_SECONDS)
    return data
```

## 4. 키 이름 설계

Redis는 모든 데이터가 키로 시작합니다. 키 이름 규칙을 정해두면 운영과 디버깅이 쉬워집니다.

```
좋은 키 이름 패턴: {도메인}:{식별자}:{목적}

session:{session_id}           → 세션 Hash
chat_history:{session_id}      → 대화 이력 List
user:status:{user_id}          → 사용자 상태 String
rate_limit:{user_id}:{minute}  → Rate limit 카운터
```

| 데이터 | 키 패턴 | 자료구조 |
|--------|---------|--------|
| 세션 | `session:{session_id}` | Hash |
| 대화 이력 | `chat_history:{session_id}` | List |
| 사용자 상태 | 세션 Hash의 `status` 필드 | - |

## 5. Redis 서버 실행

### Docker로 실행 (권장)

```bash
# Redis 컨테이너 시작
docker run --name redis-fastapi -p 6379:6379 -d redis:7

# 동작 확인
docker exec -it redis-fastapi redis-cli ping
# PONG
```

이미 컨테이너가 있다면:

```bash
docker start redis-fastapi
docker stop  redis-fastapi
```

### Redis CLI 기본 명령

```bash
# CLI 접속
docker exec -it redis-fastapi redis-cli

# 키 목록 확인
KEYS *
KEYS session:*           # 패턴으로 검색

# 키 타입 확인
TYPE session:abc         # hash

# 키 삭제
DEL session:abc

# 전체 초기화 (주의!)
FLUSHALL
```

```python
# decode_responses=False 일 때
r.get("key")  # b"value" (bytes)

# decode_responses=True 일 때
r.get("key")  # "value" (str) ← 이 방식 사용
```

## 7. 세션 생성

세션은 Hash로 저장합니다.

```python
import json
from uuid import uuid4
from datetime import datetime, timezone

SESSION_TTL_SECONDS = 1800  # 30분

def now_ts() -> str:
    return datetime.now(timezone.utc).isoformat()

def create_session(data: SessionCreate) -> dict:
    session_id = str(uuid4())
    key = f"session:{session_id}"

    r.hset(
        key,
        mapping={
            "user_id":      data.user_id,
            "display_name": data.display_name,
            "status":       "online",
            "created_at":   now_ts(),
            "last_seen_at": now_ts(),
        },
    )
    r.expire(key, SESSION_TTL_SECONDS)

    return {"session_id": session_id}
```

요청할 때는 `X-Session-Id` 헤더를 보냅니다.

```python
from fastapi import Header, HTTPException

def get_session(
    x_session_id: str | None = Header(default=None, alias="X-Session-Id"),
) -> dict:
    if not x_session_id:
        raise HTTPException(401, "X-Session-Id 헤더가 필요합니다")

    data = r.hgetall(f"session:{x_session_id}")
    if not data:
        raise HTTPException(401, "세션이 없거나 만료되었습니다")

    # 활동 시마다 TTL 갱신
    r.expire(f"session:{x_session_id}", SESSION_TTL_SECONDS)
    r.hset(f"session:{x_session_id}", "last_seen_at", now_ts())

    return data
```

## 8. 대화 이력 저장

최근 대화는 Redis List에 저장합니다.

```python
import json

CHAT_HISTORY_TTL_SECONDS = 3600  # 1시간
MAX_HISTORY_SIZE = 50             # 최근 50개 유지

def add_message(session_id: str, role: str, content: str) -> dict:
    key = f"chat_history:{session_id}"
    message = {
        "role":       role,
        "content":    content,
        "created_at": now_ts(),
    }

    r.rpush(key, json.dumps(message, ensure_ascii=False))  # 오른쪽에 추가
    r.ltrim(key, -MAX_HISTORY_SIZE, -1)                    # 최근 50개만 유지
    r.expire(key, CHAT_HISTORY_TTL_SECONDS)                # 1시간 TTL

    return message


def get_messages(session_id: str) -> list[dict]:
    key = f"chat_history:{session_id}"
    raw = r.lrange(key, 0, -1)     # 전체 조회 (왼쪽부터 오른쪽)
    return [json.loads(m) for m in raw]
```

| 명령 | 의미 |
|------|------|
| `RPUSH` | 리스트 오른쪽(끝)에 새 항목 추가 |
| `LPUSH` | 리스트 왼쪽(앞)에 새 항목 추가 |
| `LRANGE 0 -1` | 전체 메시지 조회 |
| `LTRIM -50 -1` | 최근 50개만 유지 (앞의 것 삭제) |
| `LLEN` | 리스트 길이 |
| `EXPIRE` | 오래된 대화 이력 자동 삭제 |

### `LTRIM -50 -1` 동작 원리

```
리스트: [msg1, msg2, ..., msg60]  ← 60개

LTRIM -50 -1 실행

결과: [msg11, msg12, ..., msg60]  ← 최근 50개만 유지
      msg1 ~ msg10 삭제됨
```

## 9. Supabase와 Redis의 역할 차이

이번 교시에서는 Redis만 사용했지만, 두 저장소는 역할이 다릅니다.

| 항목 | Supabase/PostgreSQL | Redis |
|------|---------------------|-------|
| 저장 위치 | 디스크 | 메모리 |
| 데이터 성격 | 영구 보관 | 임시 상태, 캐시 |
| 만료 처리 | 직접 삭제 코드 필요 | TTL 내장 |
| 조회 방식 | SQL, JOIN | 키 기반 |
| 이번 과정 역할 | 사용자/대화 영구 저장 | 세션/상태/최근 대화 |
| 재시작 시 | 데이터 유지 | 기본적으로 사라짐 |

5교시에서는 Supabase Auth와 Redis 세션을 결합합니다.

## 10. 이번 교시 API

```
GET    /redis/health
POST   /sessions
GET    /sessions/me
PATCH  /sessions/me/status
DELETE /sessions/me
POST   /chat/messages
GET    /chat/messages
GET    /metrics
```

### 실습 순서

1. Docker로 Redis 서버 실행 → `docker exec -it redis-fastapi redis-cli ping` 확인
2. `POST /sessions` → `{"user_id": "test-1", "display_name": "김학생"}` → `session_id` 복사
3. Swagger **X-Session-Id** 헤더 입력
4. `PATCH /sessions/me/status` → `{"status": "away"}` 상태 변경
5. `POST /chat/messages` → 메시지 3개 저장 (user/assistant 번갈아)
6. `GET /chat/messages` → Redis List 확인
7. Redis CLI에서 직접 확인:
   ```bash
   KEYS session:*
   HGETALL session:{session_id}
   TTL session:{session_id}
   LRANGE chat_history:{session_id} 0 -1
   ```
8. 세션 삭제 후 `GET /sessions/me` → 401 확인

## 11. 흔한 실수와 해결법

| 오류 | 원인 | 해결 |
|------|------|------|
| `redis.exceptions.ConnectionError` | Redis 서버 미실행 | `docker start redis-fastapi` |
| `AttributeError: 'bytes' object` | `decode_responses=True` 미설정 | `redis.from_url(..., decode_responses=True)` |
| 메시지가 한 줄로 합쳐져 보임 | `json.loads` 미적용 | `[json.loads(m) for m in raw]` |
| TTL이 -1 | `expire()` 미호출 | `r.expire(key, TTL_SECONDS)` 추가 |
| 세션 만료 후 `hgetall`이 `{}` 반환 | 키가 없어서 빈 딕셔너리 반환 | `if not data: raise HTTPException(401, ...)` |
| `LTRIM` 후 개수가 MAX 초과 | `LTRIM` 호출 위치 오류 | `RPUSH` 바로 다음에 `LTRIM` 호출 |
| `json.dumps` 한국어 깨짐 | `ensure_ascii=True` (기본값) | `json.dumps(msg, ensure_ascii=False)` |

## 핵심 패턴 요약

| 기능 | 코드 |
|------|------|
| Redis 연결 | `redis.from_url(REDIS_URL, decode_responses=True)` |
