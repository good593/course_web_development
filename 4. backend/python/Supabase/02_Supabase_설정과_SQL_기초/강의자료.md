## 1. Supabase란

Supabase는 **오픈소스 Firebase 대안**으로, PostgreSQL 데이터베이스와 인증·저장소·실시간 구독 기능을 함께 제공합니다.

이 과정에서 Supabase를 선택하는 이유:

| 이유 | 설명 |
|------|------|
| PostgreSQL 사용 | 업계 표준 RDBMS, 학습한 내용이 그대로 실무로 이어짐 |
| REST API 자동 생성 | Python 클라이언트(supabase-py)로 바로 사용 가능 |
| Auth 내장 | 회원가입·로그인을 직접 구현하지 않아도 됨 (3교시) |
| 무료 플랜 | 개인 프로젝트·학습에 충분 |
| 대시보드 | SQL Editor, Table Editor 등 시각적 도구 제공 |

## 2. Supabase 프로젝트 생성

### 2-1. 가입 및 프로젝트 생성

1. [supabase.com](https://supabase.com) → **Start your project** → GitHub 또는 이메일로 가입
2. **New project** 버튼 클릭
3. 아래 항목 입력:

| 항목 | 권장 값 |
|------|--------|
| Name | `fastapi-lecture` |
| Database Password | 강력한 비밀번호 (기록해 두기!) |
| Region | `Northeast Asia (Seoul)` |

4. **Create new project** 클릭 → 데이터베이스 초기화 1~2분 대기

### 2-2. 프로젝트 대시보드 구성

초기화 완료 후 보이는 메뉴:

```
좌측 메뉴
  ├── Table Editor   — 테이블 데이터를 GUI로 조회·수정
  ├── SQL Editor     — SQL 직접 실행
  ├── Authentication — 사용자 계정 관리 (3교시)
  ├── Storage        — 파일 저장
  └── Project Settings
          ├── General  — 프로젝트 URL
          └── API      — API 키
```

## 3. API 키 이해하기

**Project Settings → API** 에서 아래 값들을 확인합니다.

| 항목 | 위치 | 공개 가능 여부 | 용도 |
|------|------|---------------|------|
| Project URL | URL 섹션 | ✅ 공개 가능 | `SUPABASE_URL` |
| anon public | API Keys | ✅ 공개 가능 (RLS 필수) | 클라이언트 앱 (3교시 이후) |
| service_role | API Keys | ❌ **절대 공개 금지** | FastAPI 서버 전용 |

### service_role 키 보안 규칙

```
⚠️  service_role 키는 RLS(행 수준 보안)를 우회합니다.
    이 키를 가진 사람은 모든 테이블의 모든 데이터를 읽고 쓸 수 있습니다.

절대 안 되는 것:
  ❌ GitHub에 올리기
  ❌ 프론트엔드(React, Vue) 코드에 넣기
  ❌ 동료에게 채팅으로 전송하기

해야 하는 것:
  ✅ .env 파일에만 저장
  ✅ .env를 .gitignore에 추가
  ✅ 서버(FastAPI) 코드에서만 사용
```

## 4. SQL Editor에서 테이블 생성

### 4-1. schema.sql 실행

1. 좌측 메뉴 → **SQL Editor**
2. **+ New query** 클릭
3. 이 폴더의 `schema.sql` 파일 내용을 붙여넣기
4. 우측 상단 **RUN** 클릭
5. 좌측 **Table Editor** → `app_users`, `conversations`, `messages` 3개 확인

### 4-2. DDL 해석

DDL(Data Definition Language)은 테이블 구조를 정의하는 SQL입니다.

```sql
-- 테이블 생성
CREATE TABLE IF NOT EXISTS public.app_users (
  id           UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  username     TEXT        NOT NULL UNIQUE,
  display_name TEXT        NOT NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

각 줄의 의미:

| 코드 | 의미 |
|------|------|
| `CREATE TABLE IF NOT EXISTS` | 없을 때만 생성 (이미 있으면 오류 없이 건너뜀) |
| `UUID PRIMARY KEY` | 이 컬럼이 기본 키, UUID 타입 |
| `DEFAULT gen_random_uuid()` | 값을 넣지 않으면 자동으로 UUID 생성 |
| `TEXT NOT NULL` | 문자열, 빈 값 금지 |
| `UNIQUE` | 중복 값 금지 |
| `TIMESTAMPTZ NOT NULL DEFAULT NOW()` | 현재 시간으로 자동 설정 |

```sql
-- 외래 키 참조
CREATE TABLE IF NOT EXISTS public.conversations (
  id         UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id    UUID        NOT NULL REFERENCES public.app_users(id) ON DELETE CASCADE,
  title      TEXT        NOT NULL DEFAULT '새 대화',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

| 코드 | 의미 |
|------|------|
| `REFERENCES public.app_users(id)` | `app_users` 테이블의 `id`를 참조하는 FK |
| `ON DELETE CASCADE` | 부모 행 삭제 시 자식 행도 자동 삭제 |
| `DEFAULT '새 대화'` | title을 생략하면 '새 대화'로 저장 |

```sql
-- CHECK 제약
CREATE TABLE IF NOT EXISTS public.messages (
  role TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
  ...
);
```

`CHECK`는 허용 값 목록 외의 값이 들어오면 DB에서 오류를 냅니다.

## 5. SELECT — 데이터 조회

SQL에서 가장 많이 쓰는 명령입니다. SQL Editor에서 직접 실행해 봅니다.

### 기본 조회

```sql
-- 모든 컬럼, 모든 행
SELECT * FROM public.app_users;

-- 특정 컬럼만
SELECT id, username FROM public.app_users;

-- 별칭(Alias) 사용
SELECT id, username AS "사용자명" FROM public.app_users;
```

### 정렬

```sql
-- 최신 순 정렬 (내림차순)
SELECT * FROM public.app_users ORDER BY created_at DESC;

-- 이름 가나다 순 (오름차순, 기본값)
SELECT * FROM public.app_users ORDER BY username ASC;
SELECT * FROM public.app_users ORDER BY username;  -- ASC 생략 가능
```

### WHERE — 조건 필터링

```sql
-- 단일 조건: username이 'kim'인 사용자
SELECT * FROM public.app_users WHERE username = 'kim';

-- 복합 조건: AND
SELECT * FROM public.messages
WHERE conversation_id = '대화_UUID'
  AND role = 'user';

-- 복합 조건: OR
SELECT * FROM public.messages
WHERE role = 'user' OR role = 'assistant';

-- IN: 여러 값 중 하나
SELECT * FROM public.messages WHERE role IN ('user', 'assistant');

-- LIKE: 패턴 검색 (% = 아무 문자 0개 이상)
SELECT * FROM public.conversations WHERE title LIKE '%FastAPI%';
SELECT * FROM public.conversations WHERE title LIKE 'Python%';  -- 'Python'으로 시작

-- IS NULL / IS NOT NULL
SELECT * FROM public.conversations WHERE title IS NULL;
SELECT * FROM public.conversations WHERE title IS NOT NULL;
```

## 6. INSERT — 데이터 추가

```sql
-- 기본 INSERT
INSERT INTO public.app_users (username, display_name)
VALUES ('kim', '김학생');

-- 여러 행 동시 추가
INSERT INTO public.app_users (username, display_name) VALUES
  ('lee', '이학생'),
  ('park', '박학생');

-- DEFAULT를 사용하는 컬럼은 생략 가능 (id, created_at)
INSERT INTO public.conversations (user_id, title)
VALUES ('여기에-사용자-UUID', 'FastAPI 공부');
-- title을 생략하면 '새 대화'로 저장됨
INSERT INTO public.conversations (user_id)
VALUES ('여기에-사용자-UUID');
```

### INSERT 후 결과 확인 방법

```sql
-- 방법 1: INSERT 직후 SELECT
INSERT INTO public.app_users (username, display_name) VALUES ('test', '테스트');
SELECT * FROM public.app_users WHERE username = 'test';

-- 방법 2: RETURNING — 저장된 행 바로 반환
INSERT INTO public.app_users (username, display_name)
VALUES ('test2', '테스트2')
RETURNING *;
-- 응답에 저장된 데이터가 바로 반환됨
```

## 7. 제약 조건 동작 확인

SQL Editor에서 아래 쿼리들을 실행해서 제약이 실제로 동작하는지 확인합니다.

### UNIQUE 위반

```sql
-- 먼저 'kim' 사용자 추가
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김학생');

-- 같은 username으로 다시 추가 시도 → 오류 발생!
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김이름');
-- ERROR: duplicate key value violates unique constraint "app_users_username_key"
```

### NOT NULL 위반

```sql
-- display_name 없이 추가 시도 → 오류 발생!
INSERT INTO public.app_users (username) VALUES ('noname');
-- ERROR: null value in column "display_name" violates not-null constraint
```

### FK 위반

```sql
-- 존재하지 않는 user_id로 대화방 추가 시도 → 오류 발생!
INSERT INTO public.conversations (user_id, title)
VALUES ('00000000-0000-0000-0000-000000000000', '테스트');
-- ERROR: insert or update on table "conversations" violates foreign key constraint
```

### CHECK 위반

```sql
-- 허용되지 않은 role 값 시도 → 오류 발생!
INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화_UUID', 'bot', '안녕');
-- ERROR: new row for relation "messages" violates check constraint
```

## 8. 실습 순서

1. Supabase 프로젝트 생성 완료
2. **SQL Editor** → `schema.sql` 실행
3. **Table Editor** → 3개 테이블 확인
4. SQL Editor에서 사용자 2명 INSERT:

```sql
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김학생');
INSERT INTO public.app_users (username, display_name) VALUES ('lee', '이학생');
```

5. `SELECT * FROM public.app_users;` — 2명 확인
6. `kim`의 UUID를 복사하여 대화방 추가:

```sql
INSERT INTO public.conversations (user_id, title)
VALUES ('복사한-UUID', 'FastAPI 공부');
```

7. 대화방의 UUID를 복사하여 메시지 추가:

```sql
INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화방-UUID', 'user', '안녕하세요!');

INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화방-UUID', 'assistant', '안녕하세요! 무엇을 도와드릴까요?');
```

8. SELECT로 저장된 데이터 조회:

```sql
SELECT * FROM public.messages ORDER BY created_at ASC;
```

## 9. 흔한 실수와 해결법

| 오류 메시지 | 원인 | 해결 |
|------------|------|------|
| `relation "app_users" does not exist` | schema.sql 미실행 | SQL Editor에서 schema.sql 재실행 |
| `duplicate key value violates unique constraint` | username 중복 | 다른 username 사용 |
| `null value in column "display_name"` | 필수 컬럼 누락 | 모든 NOT NULL 컬럼 값 입력 |
| `violates foreign key constraint` | 없는 UUID 참조 | 먼저 부모 행을 INSERT 후 UUID 사용 |
| `violates check constraint` | role에 잘못된 값 | `user`, `assistant`, `system` 중 하나 사용 |
| SQL Editor에서 아무 결과 없음 | SELECT 조건에 맞는 행 없음 | WHERE 조건 확인 또는 SELECT * 로 전체 조회 |

## 핵심 패턴 요약

| 작업 | SQL |
|------|-----|
| 테이블 생성 | `CREATE TABLE IF NOT EXISTS ... (...)` |
| 전체 조회 | `SELECT * FROM 테이블` |
| 컬럼 선택 | `SELECT col1, col2 FROM 테이블` |
| 조건 조회 | `WHERE col = 값` |
| 최신순 정렬 | `ORDER BY created_at DESC` |
| 단건 추가 | `INSERT INTO 테이블 (col1, col2) VALUES (v1, v2)` |
| 결과 바로 반환 | `INSERT ... RETURNING *` |
