# 9교시: Redis 기초와 세션 관리

**소요시간:** 90분 (이론 30분 + 실습 60분)  
**사전 지식:** 8교시(Supabase Auth), Docker 기본 명령어

## 학습 목표

- Redis가 PostgreSQL과 다른 이유와 용도를 설명한다
- String, Hash, List, Set, Sorted Set의 특성과 용도를 구분한다
- `TTL(Time To Live)`로 자동 만료되는 세션을 구현한다
- `X-Session-Id` 헤더로 사용자 상태를 유지한다
- Redis List로 최근 대화 이력을 저장하고 `LTRIM`으로 크기를 제한한다

## 1. Redis란 무엇인가

Redis는 **메모리에 데이터를 저장**하는 초고속 키-값 저장소입니다.

### PostgreSQL과 비교

| 항목 | PostgreSQL (Supabase) | Redis |
|------|----------------------|-------|
| 저장 위치 | 디스크 | 메모리 |
| 속도 | 수 ms ~ 수십 ms | 수십 µs (마이크로초) |
| 재시작 후 | 데이터 유지 | 기본적으로 사라짐 |
| 쿼리 방식 | SQL (JOIN, 집계) | 키 기반 직접 접근 |
| 만료 처리 | 직접 삭제 코드 필요 | TTL 내장 |
| 주 용도 | 영구 데이터 저장 | 세션, 캐시, 임시 상태 |

### Redis를 써야 하는 상황

| 사용 사례 | 이유 |
|-----------|------|
| 로그인 세션 | TTL로 자동 만료, 빠른 조회 |
| 사용자 현재 상태 (online/away) | 자주 바뀌고, DB에 저장할 필요 없음 |
| 최근 N개 대화 이력 | LLM 컨텍스트용 빠른 조회 |
| DB 조회 결과 캐시 | 동일 쿼리 반복 방지 |
| Rate Limit | 짧은 시간 요청 횟수 집계 |

## 3. Redis 자료구조

### String — 가장 단순한 키-값

```bash
SET user:count 42          # 저장
GET user:count             # "42"
INCR user:count            # "43" (원자적 증가)
DECR user:count            # "42"
SET session:abc "user-1"   # 세션 토큰 저장
EXISTS session:abc         # 1 (있음), 0 (없음)
```

### Hash — 딕셔너리처럼 여러 필드

```bash
HSET session:abc user_id "u1" display_name "김학생" status "online"
HGET  session:abc user_id        # "u1"
HGETALL session:abc
# 1) "user_id"
# 2) "u1"
# 3) "display_name"
# 4) "김학생"
# 5) "status"
# 6) "online"
HSET session:abc status "away"   # 한 필드만 수정 (나머지 유지)
HDEL session:abc status          # 한 필드만 삭제
```

**→ 이번 실습에서 세션 저장에 사용합니다.**

### List — 순서 있는 목록

```bash
RPUSH chat:abc '{"role":"user","content":"안녕"}'       # 오른쪽에 추가
RPUSH chat:abc '{"role":"assistant","content":"안녕요"}' # 오른쪽에 추가
LRANGE chat:abc 0 -1    # 전체 조회 (왼쪽부터)
LLEN   chat:abc         # 길이 2
LTRIM  chat:abc -10 -1  # 최근 10개만 유지 (앞 것 삭제)
```

**→ 이번 실습에서 대화 이력 저장에 사용합니다.**

### Set — 중복 없는 집합

```bash
SADD  online_users "user1"
SADD  online_users "user2"
SADD  online_users "user1"   # 중복 무시됨
SMEMBERS online_users        # {"user1", "user2"}
SISMEMBER online_users "user1"  # 1 (있음)
SREM  online_users "user1"
SCARD online_users           # 집합 크기
```

### Sorted Set — 점수(score) 기준 정렬

```bash
ZADD  leaderboard 100 "user1"
ZADD  leaderboard 200 "user2"
ZADD  leaderboard 150 "user3"
ZRANGE leaderboard 0 -1 WITHSCORES  # 점수 오름차순
# user1 100 / user3 150 / user2 200
ZREVRANGE leaderboard 0 2           # 상위 3명 (점수 내림차순)
```

### 자료구조 선택 가이드

| 자료구조 | 적합한 경우 | 이번 실습 |
|----------|-----------|-----------|
| String | 단순 값, 카운터 | - |
| Hash | 객체처럼 여러 속성 | ✅ 세션 저장 |
| List | 순서 있는 목록, 최근 N개 | ✅ 대화 이력 |
| Set | 중복 없는 집합, 멤버십 확인 | - |
| Sorted Set | 랭킹, 시간순 데이터 | - |

## 4. TTL (Time To Live)

TTL은 키가 **자동으로 사라지기까지 남은 시간(초)**입니다.

```bash
SET session:abc "user-1"
EXPIRE session:abc 1800    # 30분 후 자동 삭제

TTL session:abc            # 남은 초 확인 (예: 1797)
TTL session:abc            # 만료 후: -2 (키 없음)
TTL session:xyz            # 존재하지 않는 키: -2
TTL session:neverexpire    # TTL 없는 키: -1

PERSIST session:abc        # TTL 제거 → 영구 보관
```

### Python에서 TTL 설정

```python
r.hset("session:abc", mapping={"user_id": "u1"})
r.expire("session:abc", 1800)   # 30분
r.ttl("session:abc")            # 남은 초 반환
```

### Sliding Expiry (활동 시마다 TTL 갱신)

```python
def get_session(session_id: str) -> dict:
    data = r.hgetall(f"session:{session_id}")
    if not data:
        raise HTTPException(401, "세션이 없거나 만료되었습니다")

    # 요청이 올 때마다 TTL을 30분으로 갱신
    r.expire(f"session:{session_id}", 1800)
    return data
```

```
사용자가 30분마다 한 번씩 활동하면 → 세션 영구 유지
마지막 활동 후 30분 경과 → 세션 자동 만료
```

## 5. Redis 키 이름 설계

Redis는 모든 데이터가 키로 시작합니다.  
키 이름에 규칙을 정해두면 운영과 디버깅이 쉬워집니다.

```
권장 패턴: {도메인}:{식별자}

session:{session_id}           → 세션 Hash
chat_history:{session_id}      → 대화 이력 List
user:count                     → 사용자 수 String
online:{user_id}               → 온라인 여부
```

```bash
# Redis CLI에서 확인
KEYS *                      # 전체 키 목록 (운영 환경에서 사용 금지!)
KEYS session:*              # session: 으로 시작하는 키
TYPE session:abc            # hash
TYPE chat_history:abc       # list
DEL session:abc             # 키 삭제
FLUSHALL                    # 전체 초기화 (⚠️ 주의!)
```

## 6. Python Redis 클라이언트 초기화

```python
import redis

r = redis.from_url(
    "redis://localhost:6379/0",
    decode_responses=True,   # bytes → str 자동 변환
)

r.ping()  # True — 연결 확인
```

### decode_responses=True의 중요성

```python
# decode_responses=False (기본값)
r.set("key", "hello")
r.get("key")  # b"hello" (bytes)

# decode_responses=True (권장)
r.set("key", "hello")
r.get("key")  # "hello" (str) ← 이것을 사용
```

`decode_responses=True`가 없으면 모든 값이 `bytes` 타입으로 반환되어  
딕셔너리 비교나 JSON 파싱 시 `AttributeError: 'bytes' object`가 발생합니다.

## 7. 세션 생성 구현

세션은 Hash로 저장하고 TTL을 30분으로 설정합니다.

```python
from uuid import uuid4
import time

SESSION_TTL_SECONDS = 1800  # 30분

def session_key(session_id: str) -> str:
    return f"session:{session_id}"


@app.post("/sessions", status_code=201)
def create_session(data: SessionCreate):
    session_id = str(uuid4())
    key = session_key(session_id)

    r.hset(
        key,
        mapping={
            "user_id":      data.user_id,
            "display_name": data.display_name,
            "status":       "online",
            "created_at":   int(time.time()),
            "last_seen_at": int(time.time()),
        },
    )
    r.expire(key, SESSION_TTL_SECONDS)

    return {
        "session_id": session_id,
        "ttl_seconds": r.ttl(key),
    }
```

## 8. X-Session-Id 헤더로 세션 조회

```python
from fastapi import Header, HTTPException

def get_session(
    x_session_id: str | None = Header(default=None, alias="X-Session-Id"),
) -> dict:
    if not x_session_id:
        raise HTTPException(401, "X-Session-Id 헤더가 필요합니다")

    data = r.hgetall(session_key(x_session_id))
    if not data:
        raise HTTPException(401, "세션이 없거나 만료되었습니다")

    # 활동 시마다 TTL 갱신 (Sliding Expiry)
    r.expire(session_key(x_session_id), SESSION_TTL_SECONDS)
    r.hset(session_key(x_session_id), "last_seen_at", int(time.time()))

    return data | {"session_id": x_session_id}
```

엔드포인트에서:

```python
@app.get("/sessions/me")
def get_my_session(session: dict = Depends(get_session)):
    return {
        **session,
        "ttl_seconds": r.ttl(session_key(session["session_id"])),
    }
```

### Swagger에서 X-Session-Id 헤더 입력 방법

1. `POST /sessions` → Body에 `{"user_id": "test-1", "display_name": "김학생"}` → `session_id` 복사
2. Swagger UI → Headers 섹션 또는 각 엔드포인트의 Parameters에서 `X-Session-Id` 입력

> `X-Session-Id`는 표준 헤더가 아니라 커스텀 헤더입니다.  
> FastAPI의 `Header` 파라미터로 받을 때 `alias="X-Session-Id"`를 지정합니다.

## 9. 대화 이력 저장 — Redis List

```python
import json

CHAT_HISTORY_TTL = 3600  # 1시간
MAX_HISTORY = 50          # 최근 50개 유지


@app.post("/chat/messages", status_code=201)
def add_message(data: ChatMessageCreate, session: dict = Depends(get_session)):
    key = f"chat_history:{session['session_id']}"
    message = {
        "role":       data.role,
        "content":    data.content,
        "created_at": int(time.time()),
    }

    r.rpush(key, json.dumps(message, ensure_ascii=False))  # 오른쪽에 추가
    r.ltrim(key, -MAX_HISTORY, -1)                         # 최근 50개만 유지
    r.expire(key, CHAT_HISTORY_TTL)                        # TTL 설정

    return message | {"history_length": r.llen(key)}


@app.get("/chat/messages")
def list_messages(session: dict = Depends(get_session)):
    key = f"chat_history:{session['session_id']}"
    raw = r.lrange(key, 0, -1)          # 전체 조회
    return [json.loads(m) for m in raw]  # JSON 파싱
```

### LTRIM 동작 원리

```
메시지 추가 전: [msg1, msg2, ..., msg55]  ← 55개

RPUSH → [msg1, msg2, ..., msg55, msg56]   ← 56개

LTRIM -50 -1 실행:
  -1 = 마지막 (msg56)
  -50 = 뒤에서 50번째 (msg7)
  → [msg7, msg8, ..., msg56]              ← 50개 (msg1~msg6 삭제)
```

### ensure_ascii=False의 중요성

```python
# ❌ 기본값 ensure_ascii=True
json.dumps({"content": "안녕"})
# '{"content": "\\uc548\\ub155"}'  ← 한국어가 유니코드 이스케이프로 저장됨

# ✅ ensure_ascii=False
json.dumps({"content": "안녕"}, ensure_ascii=False)
# '{"content": "안녕"}'  ← 한국어 그대로 저장
```

## 11. 이번 교시 API

```
GET    /redis/health           — Redis 연결 상태 확인
POST   /sessions               — 세션 생성 (session_id 반환)
GET    /sessions/me            — 세션 정보 조회 (X-Session-Id 헤더)
PATCH  /sessions/me/status     — 상태 변경 (online/away/busy)
DELETE /sessions/me            — 세션 삭제
POST   /chat/messages          — 메시지 저장
GET    /chat/messages          — 대화 이력 조회
GET    /metrics                — 세션/이력 키 수 확인
```

### 실습 순서

1. `docker run --name redis-fastapi -p 6379:6379 -d redis:7`
2. `GET /redis/health` → `{"ok": true}` 확인
3. `POST /sessions` → session_id 복사
4. `GET /sessions/me` (X-Session-Id 헤더 포함) → 세션 정보 확인
5. `POST /chat/messages` → 메시지 3개 저장
6. `GET /chat/messages` → 목록 확인
7. Redis CLI에서 직접 확인:
   ```bash
   KEYS *
   HGETALL session:{id}
   TTL session:{id}
   LRANGE chat_history:{id} 0 -1
   ```
8. `DELETE /sessions/me` → 삭제 후 `GET /sessions/me` → **401** 확인

## 12. 흔한 실수와 해결법

| 오류 | 원인 | 해결 |
|------|------|------|
| `redis.exceptions.ConnectionError` | Redis 서버 미실행 | `docker start redis-fastapi` |
| `AttributeError: 'bytes'` | `decode_responses=True` 미설정 | `redis.from_url(..., decode_responses=True)` |
| 한국어 메시지 깨짐 | `ensure_ascii=True` (기본값) | `json.dumps(msg, ensure_ascii=False)` |
| TTL이 -1 | `r.expire()` 미호출 | RPUSH/HSET 직후 `r.expire(key, TTL)` 추가 |
| 세션 만료 후 `{}` 반환 | `hgetall` 빈 딕셔너리 | `if not data: raise HTTPException(401, ...)` |
| `LTRIM` 후 개수 초과 | RPUSH 후 LTRIM 순서 오류 | RPUSH 바로 다음에 LTRIM 호출 |
| 메시지가 한 문자열로 합쳐짐 | `json.loads` 미적용 | `[json.loads(m) for m in raw]` |

| 기능 | 코드 |
|------|------|
