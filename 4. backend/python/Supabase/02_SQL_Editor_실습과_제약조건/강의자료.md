# 2교시: SQL Editor 실습 — 제약조건·CRUD·JOIN·집계

**소요시간:** 90분 (실습 위주)
**사전 지식:** 1교시(Supabase 프로젝트 설정, ERD), SQL 기초(SELECT/INSERT/UPDATE/DELETE/JOIN/GROUP BY)

---

> 이 교시는 SQL 문법 자체를 새로 가르치지 않습니다. **PostgreSQL SQL을 이미 안다는 전제**로, Supabase의 SQL Editor·Table Editor에서 그 문법이 어떻게 동작하는지, 그리고 이 강의 스키마(`app_users`/`conversations`/`messages`)에 어떻게 적용되는지를 실습합니다.

## 학습 목표

- `schema.sql`을 SQL Editor에서 실행하고 제약 조건이 실제로 동작하는 것을 확인한다
- `UPDATE`/`DELETE`를 안전하게 사용하고 `ON DELETE CASCADE` 동작을 직접 확인한다
- JOIN·GROUP BY·LIMIT/OFFSET을 이 강의 스키마에 적용해 실습한다
- Supabase Table Editor와 SQL Editor를 상황에 맞게 활용한다

---

## 1. schema.sql 실행과 DDL 확인

1. 좌측 메뉴 → **SQL Editor** → **+ New query**
2. 이 폴더(또는 1교시 폴더)의 `schema.sql` 내용을 붙여넣고 **RUN**
3. 좌측 **Table Editor** → `app_users`, `conversations`, `messages` 3개 테이블 확인

이 스키마에는 `NOT NULL`, `UNIQUE`, `CHECK`, `REFERENCES ... ON DELETE CASCADE` 제약이 이미 포함되어 있습니다. 바로 동작을 확인해 봅니다.

---

## 2. 제약 조건 동작 확인

SQL Editor에서 아래 쿼리들을 실행해서 제약이 실제로 동작하는지 확인합니다.

### UNIQUE 위반

```sql
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김학생');

-- 같은 username으로 다시 추가 시도 → 오류 발생!
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김이름');
-- ERROR: duplicate key value violates unique constraint "app_users_username_key"
```

### NOT NULL / FK / CHECK 위반

```sql
-- NOT NULL 위반
INSERT INTO public.app_users (username) VALUES ('noname');
-- ERROR: null value in column "display_name" violates not-null constraint

-- FK 위반: 존재하지 않는 user_id
INSERT INTO public.conversations (user_id, title)
VALUES ('00000000-0000-0000-0000-000000000000', '테스트');
-- ERROR: violates foreign key constraint

-- CHECK 위반: 허용되지 않은 role
INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화_UUID', 'bot', '안녕');
-- ERROR: violates check constraint
```

---

## 3. 데이터 준비 실습

```sql
INSERT INTO public.app_users (username, display_name) VALUES ('kim', '김학생');
INSERT INTO public.app_users (username, display_name) VALUES ('lee', '이학생');

-- kim의 UUID를 복사하여 대화방 추가
INSERT INTO public.conversations (user_id, title)
VALUES ('복사한-UUID', 'FastAPI 공부')
RETURNING *;  -- 저장된 행을 바로 반환

-- 대화방의 UUID를 복사하여 메시지 추가
INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화방-UUID', 'user', '안녕하세요!');
INSERT INTO public.messages (conversation_id, role, content)
VALUES ('대화방-UUID', 'assistant', '안녕하세요! 무엇을 도와드릴까요?');
```

## 4. UPDATE·DELETE — 안전 수칙과 CASCADE 확인

```sql
-- ⚠️ WHERE 없이 실행하면 전체가 수정/삭제됩니다
UPDATE public.app_users SET display_name = '테스트';        -- ❌ 위험
UPDATE public.app_users SET display_name = '테스트'
  WHERE id = '특정-사용자-UUID' RETURNING *;                  -- ✅ 안전

DELETE FROM public.messages;                                  -- ❌ 위험
DELETE FROM public.messages WHERE id = '메시지-UUID';         -- ✅ 안전
```

### CASCADE 삭제 확인

```sql
-- 삭제 전 메시지 수 확인
SELECT COUNT(*) FROM public.messages WHERE conversation_id = '대화방-UUID';

-- 대화방 삭제 → schema.sql의 ON DELETE CASCADE에 의해 메시지도 자동 삭제됨
DELETE FROM public.conversations WHERE id = '대화방-UUID';

-- 메시지 자동 삭제 확인 (빈 결과)
SELECT COUNT(*) FROM public.messages WHERE conversation_id = '대화방-UUID';
```

## 5. JOIN 실습 — 3개 테이블 연결

```sql
SELECT
  u.username,
  u.display_name,
  c.title         AS conversation_title,
  m.role,
  m.content,
  m.created_at
FROM public.messages m
JOIN public.conversations c ON c.id = m.conversation_id
JOIN public.app_users    u ON u.id = c.user_id
ORDER BY m.created_at ASC;
```

**과제**: 사용자명, 대화 제목, 메시지 내용을 한 번에 조회하는 쿼리를 직접 작성해 본다.

---

## 6. 집계 실습 — GROUP BY, HAVING

```sql
-- 사용자별 대화 수
SELECT u.username, COUNT(c.id) AS 대화수
FROM public.app_users u
LEFT JOIN public.conversations c ON c.user_id = u.id
GROUP BY u.id, u.username
ORDER BY 대화수 DESC;

-- 메시지가 5개 이상인 대화방만 조회 (HAVING — 집계 후 필터)
SELECT conversation_id, COUNT(*) AS 메시지수
FROM public.messages
GROUP BY conversation_id
HAVING COUNT(*) >= 5
ORDER BY 메시지수 DESC;
```

**과제**: 각 사용자가 가진 대화방 수, 각 대화방의 메시지 수를 조회하라.

---

## 7. 페이지네이션 — LIMIT/OFFSET

```sql
-- 최신 메시지 10개만
SELECT * FROM public.messages ORDER BY created_at DESC LIMIT 10;

-- 2페이지 (11번째 ~ 20번째)
SELECT * FROM public.messages ORDER BY created_at DESC LIMIT 10 OFFSET 10;
```

**패턴:** `OFFSET = (페이지 번호 - 1) × LIMIT` — 항상 `ORDER BY`와 함께 사용해야 결과가 일관됩니다.

---

## 8. Supabase Table Editor 활용

SQL만으로는 직관적이지 않을 때 Table Editor를 사용합니다.

- **테이블 내용 보기**: 좌측 메뉴 → Table Editor → 테이블 선택
- **행 직접 추가/수정/삭제**: `+ Insert row`, 셀 클릭 편집, 행 선택 후 Delete
- **필터/정렬**: 상단 바의 Filter, Sort 버튼

> **팁**: Table Editor는 소량 데이터 확인에 좋고, 복잡한 조건이나 JOIN은 SQL Editor에서 합니다.

## 흔한 실수와 해결법

| 오류/실수 | 원인 | 해결 |
|------|------|------|
| `relation "app_users" does not exist` | schema.sql 미실행 | SQL Editor에서 schema.sql 재실행 |
| `UPDATE`/`DELETE` WHERE 없이 실행 | 전체 행이 수정/삭제됨 | 반드시 WHERE 절 포함, 실행 전 SELECT로 먼저 확인 |
| JOIN ON 조건 빠뜨림 | 카테시안 곱 (행 수 폭발) | ON 절 반드시 포함 |
| GROUP BY 없이 집계 컬럼과 일반 컬럼을 함께 SELECT | 오류 발생 | SELECT의 비집계 컬럼은 GROUP BY에 포함 |
| ORDER BY 없이 OFFSET | 페이지별 결과 일관성 없음 | 항상 ORDER BY와 함께 사용 |
